SPRING BOOT:

Spring:
    Spring is a popular Java framework used to build large, scalable applications. It helps developers by providing tools and design patterns like dependency injection, making code more modular and easier to manage. However, using Spring alone often requires a lot of manual setup, configuration files, and managing many different components like databases, security, and servers. That’s where Spring Boot comes in.

Spring Boot:
    Spring Boot is built on top of Spring and is designed to simplify the process of building Spring-based applications. It reduces the amount of code and configuration needed by providing automatic setup, default settings, and built-in tools. It even includes an embedded server like Tomcat, so you can run your application without installing or configuring an external server. Think of Spring Boot as a ready-made shortcut for using the Spring framework — it allows developers to create production-ready apps quickly with minimal hassle.

Maven:

    In short: Maven helps you build and manage Java projects easily.

Architecture:
    In a typical Spring Boot application, the flow starts with a Controller, which handles incoming HTTP requests from the frontend or client. The controller acts as the entry point to your backend system. When a request arrives (like a GET or POST), the controller maps that request to a method using annotations like @GetMapping or @PostMapping. This method doesn’t handle business logic directly but delegates it to the Service layer.
    
    Service Layer is annotated with @Service. The service layer contains the core business logic — any calculations, validations, or decisions are made here. The service layer, in turn, interacts with the Repository layer

    Repository Layer is annotated with @Repository. This layer handles all the communication with the database. It uses Spring Data JPA to abstract out SQL queries, so you typically use interfaces that extend JpaRepository or CrudRepository.

    Frontend (UI) → Controller → Service → Repository → Database → Repository → Service → Controller → Frontend (Response)

IOC:
    In Spring, the IoC (Inversion of Control) container is the core part of the framework that manages the lifecycle and dependencies of objects (called beans). Instead of your code creating objects manually using new, Spring creates and manages them for you. This concept is called Inversion of Control, because control of object creation is "inverted" from the developer to the container.
    Application Context is a way to acheive IOC Container.
    IOC scans the provided package and all the classes in it but only registers those classe which has @Component annotation on them.

Dependency Injection:
    Dependency Injection is a type of IoC. It means that instead of a class creating its own dependencies, those dependencies are injected by the container, typically through constructor injection or field injection. This promotes loose coupling, easier testing, and better structure.

    Eg.
        Spring Boot example using your Dog and Car classes, demonstrating constructor-based Dependency Injection (DI) the traditional way Spring does it.
        
        1. Dog class — mark it as a Spring bean with @Component

        import org.springframework.stereotype.Component;

        @Component
        public class Dog 
        {
            public void bark() 
            {
                System.out.println("Dog is barking!");
            }
        }

        2. Car class — inject Dog via constructor

        import org.springframework.stereotype.Component;

        @Component
        public class Car 
        {

            @Autowired
            private Dog dog;

            // Spring will automatically inject Dog bean here
            public Car(Dog dog) 
            {
                this.dog = dog;
            }

            public void start() 
            {
                System.out.println("Car started.");
                dog.bark();
            }
        }

Bean:
    What is a Bean?
    A Bean in Spring is simply an object that is managed by the Spring IoC container. When you mark a class with annotations like @Component, @Service, @Repository, or define it explicitly in configuration, Spring creates and controls its lifecycle — from instantiation to destruction. These beans are the building blocks of your application.

    In traditional Java, you create objects yourself with new. In Spring, beans are created and injected automatically by the container to manage dependencies cleanly.

Annotations:
    Annotations are simply special markers or metadata in the code that provide information to the compiler or the framework (like Spring) about how to handle certain parts of your program. They don’t change the logic directly but tell the framework what to do with classes, methods, or fields—kind of like instructions attached to your code.

    Some important Spring Boot annotations you must know:
        > @SpringBootApplication
            Marks the main class of a Spring Boot app. It’s a combination of @Configuration, @EnableAutoConfiguration, and @ComponentScan. Basically, it tells Spring: “Start here, set up everything automatically, and scan for components.”

        > @Component
            Spring scans and registers classes with this annotation as beans in IOC container.

        > @Service
            A specialized form of @Component used for service-layer classes (business logic). It’s mainly for clarity and semantics.

        > @Repository
            Another specialized @Component used on data access layers (like DAOs). It also helps with exception translation related to database errors.

        > @Controller
            Marks a class as a web controller to handle HTTP requests in Spring MVC.

        > @RestController
            A shorthand for @Controller + @ResponseBody. It tells Spring that the class will serve RESTful responses (JSON/XML).

        > @Autowired
            Marks a field, constructor, or setter method for dependency injection.

        > @RequestMapping / @GetMapping / @PostMapping
            Used in controllers to map HTTP requests to handler methods.

        > @Entity
            Marks a class as a JPA entity (database table mapping).

        > @Id
            Marks a field as the primary key in an entity.

@SpringBootApplication:
    @SpringBootApplication is a special annotation in Spring Boot that marks the main entry point of your application. You put it on the class that contains the main() method. When you run the app, Spring Boot looks at this annotation and knows:

    “Start everything from here. Set up my app, scan all the components, and wire everything automatically.”

    It’s not just one annotation — it’s a combination of three important annotations:
    > @Configuration:
        "This class can define beans (objects) for the application."
        It's like saying this class is a setup/config file for Spring.

    > @EnableAutoConfiguration:
        Automatically configure everything based on what’s on the classpath."
        For example, if it sees a database dependency, it will auto-configure a datasource. This is why you don’t need to write long XML or Java config for most common tasks.

    > @ComponentScan:
        "Look in this package and all sub-packages for components (@Component, @Service, @Repository, @Controller) and register them as beans."

    @SpringBootApplication
    public class MyApp {
        public static void main(String[] args) {
            SpringApplication.run(MyApp.class, args);
        }
    }
